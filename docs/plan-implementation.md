# 教员方案落地记录

本轮在已有持续对话与议题管理上，补齐原话来源、可纠正记忆、史料主张检查、现实支持路由和质量观测。原产品方案保留为设计基线；本文记录研发实现与验证边界。

## 实现与验收

| 方案要求 | 本轮实现 | 验证方式 |
| --- | --- | --- |
| 理解有原话来源 | 每条记录有稳定ID、来源轮次、摘录、时间、暂定或用户确认状态；无来源的旧摘要不补造原话 | 来源匹配、旧数据迁移及真实模型样例 |
| 用户纠正与停用 | 确认、停用、恢复、更正；更正保留旧版。停用条件不能通过无来源的同义改写复活 | HTTP、多轮恢复及浏览器回归 |
| 目标与复盘变化 | 保留阶段目标前后版本及复盘记录，行动实施仍由用户报告 | 目标撤回、纠正、反馈与状态回归 |
| 主张与直接引语 | 普通回答发布前核对可识别历史引语的逐字片段与日期资格；用户原话与现代概念分别处理 | 改字、伪造出处、过期资格、用户摘录及上限绕过回归 |
| 历史案例结构 | 10个稳定定义，当前9个具备有限事实资格；包括事实、历史条件、未知、类比及不可类比范围 | 资格撤回、原记录变化及精确ID回查 |
| 手机就近理解和下一步 | 输入框上方呈现目标摘要与已采纳步骤，可展开完整记录 | 390px、320px截图与行为检查 |
| 用户自愿反馈 | 按实际答复轮次反馈有帮助、未帮助、事实或依据问题；不替用户接受行动 | 跨账户、跨轮、导出、删除与临时模式验证 |
| 现实支持边界 | 紧迫安全回应先承接、禁史料和网页工具、无行动卡；专业问题不强制历史类比 | 普通、小说、专业与紧迫情境的独立测试 |
| 版本与用量观测 | 记录加载代码、提示词、知识版本、资料指纹、模型调用及工具计时；供应商未报用量时未知 | HTTP/CLI上下文隔离、用量解析、指纹稳定性测试 |
| 质量看板 | 最近30天持久议题的有效内容和完整答复P50/P95、自愿反馈、失败分类及用量覆盖 | 管理员权限、聚合隐私、失败重试和删除回归 |
| 多轮评测与试用准备 | 60段、240轮合成材料，以及访谈和成人试用执行材料 | 数据结构检查；实际评阅和真人试用分别记录 |

## 重要边界

原话摘录只帮助核对模型理解，不能自动证明概括准确。“用户确认”与历史资料的“已核”是不同资格。

格式和引语问题共用最多一次预算内修复；好答不增加调用。无资格引语只能删除相应断言或说明缺口，不能去掉引号伪装转述。主张清单覆盖显式引用与可识别的历史引语。逐字检查不证明转述蕴含、现代建议有效，也不覆盖所有自然语言归因写法；超过历史引语核对上限时会明确拒绝发布，不能截断后错误放行。

现有案例缺少独立历史效果资料，结果证据保持空缺，不声称已补齐8至10个完整成功或失败案例。内容编辑、独立效果核验与争议处理仍需继续。

后台统计是运行样本。临时对话、首次失败或取消不计入持久统计；反馈是自愿样本，不可当作全部用户的准确率。费用换算与供应商用量缺失时不估造数字。代码和知识版本按加载部署记录，资料指纹按实际使用的内容与资格计算，排除检索分数变化。

本应用不主动联络、报警或持续监护，也未开展真人试用或证明长期陪伴效果。用户访谈、2至4周成人试用、更多独立案例核验、语音及授权回访按方案后续阶段推进；公开服务前的实际部署和运营条件需另行落实。

## 运行验证

```sh
python3 -m unittest discover -q
npm run test:ui
npm run test:ui:plan
npm run test:ui:legacy
```

三套浏览器测试均使用隔离数据库与明确的模型替身。`npm run test:live:product` 和 `npm run test:live:plan` 会明确调用真实服务；原始合成测试回答仅存本机忽略目录，需人工审阅。当前验证结果见 [发布验证记录](release-validation.json)。
