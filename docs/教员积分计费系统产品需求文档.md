# 教员积分计费系统产品需求文档

研发与验收评审稿  版本 1.1  2026年10月27日

本文将免登录体验、每日赠送、模型费用换算和访客转账户拆成可开发、可对账、可验收的规则，面向产品、研发、测试与运营负责人。配套《教员访客体验与积分系统产品功能方案》解释交互和产品取舍。本文件是待实施需求，不是开发完成报告。

**核心约束。** 100积分等于0.10元人民币；访客一次性100，账户每天100且当天未用完清空；所有扣费由服务端按可核验用量结算；注册后原议题可继续。用户已确认“兑换”仅指对话，首版没有充值或兑换码。

### 已确认与推荐参数

固定换算、访客100和每日100为用户已确认规则。以下参数是本方案的推荐默认值：访客额度从首次发放起180天固定有效；访客内容及本机缓存闲置180天清理；每日以Asia/Shanghai日期为准；用量未知冻结最多24小时；单一身份同时最多一个生成请求；每账户存续期最多接收一次访客余额。上线前将参数写入带版本的配置，调整不能追溯缩短已发额度期限。

当前代码有登录用户会话、SQLite存储、流式生成和输入输出用量汇总；尚没有访客钱包、缓存分桶计费、价格版本或积分账本，现有cost字段不能作为已完成的费用核算。实施时沿用现有对话质量和引用校验链，覆盖其每一笔正常模型调用。

## 二 术语与金额精度

| 术语 | 定义 |
| --- | --- |
| principal | 服务端认证出的guest或user身份，必须带类型与独立ID |
| workspace | 当前身份可访问的访客议题与消息空间，可整体归入一个账户 |
| wallet | 服务端钱包，记录额度批次、冻结、账本和归属 |
| lot | 一笔额度批次，具有来源、原始数量、到期时间和剩余额度 |
| reservation | 一个用户请求的冻结记录，与批次分配和报价绑定 |
| request与call | 一次用户生成请求及其内部多次供应商模型调用 |
| supplier_cost与user_charge | 供应商实际费用与向用户计费的金额，必须分别保存 |
| available与held | 未到期可用额度与已为特定请求冻结的额度，均不得为负 |

金额中间计算使用十进制定点，人民币至少保留12位小数，不用二进制浮点直接算账。积分以整数微积分保存，1000000微积分等于1积分。每个请求汇总所有可向用户收费的调用后，仅一次向上舍入到0.000001积分，禁止逐token、逐桶、逐调用先取整。

用户扣分算法为“本轮用户计费金额乘1000，再向上取到六位积分小数”。不设每次最低1积分。最终扣分不高于本轮已授权冻结额度。主界面可用余额向下展示两位小数；小于0.01且大于0时显示“低于0.01积分”。消费小于0.01也显示“低于0.01积分”，展开显示六位值，不能显示为免费。API返回金额和积分十进制字符串及整数微积分，禁止客户端重算权威余额。

## 三 访客身份和访问控制

### F01 身份建立

首次打开页面创建访客空间但不发放额度；第一条通过输入及风险检查的有效请求幂等领取100积分。领取后服务故障不收回额度。浏览、预加载和无效输入不触发领取。风险拦截不得先创建多笔赠送再回滚。

凭证分为四种职责：浏览器试用去重标记、匿名钱包恢复能力、访客内容访问能力、账户登录会话。去重标记不能用于读取内容或花钱；钱包恢复能力只能访问未归入账户的原匿名钱包；内容凭证不能冒充账户。凭证由服务端签发并使用第一方HttpOnly、生产HTTPS下Secure、SameSite约束与安全轮换，服务端保存摘要或安全等价表示。客户端传入的guest_id、IP或localStorage余额不能获得授权。

访客身份不能使用共享user_id等于0。IP及风险HMAC只作反滥用信号；不同IP不自动产生新资格，相同IP不自动合并用户。IP、身份凭证和内部账务明细不送入模型提示词。代理部署仅信任明确配置的代理链，忽略客户端伪造的转发头。跨设备不支持凭IP恢复；丢失有效凭证后，仅靠本地可编辑ID不能找回服务端记录。

### 授权覆盖

聊天、流式重连、议题列表、消息、理解修正、行动复盘、记忆、引用证据、反馈、导出和删除接口都必须验证principal及资源归属。访客仅访问自己的空间；账户仅访问自己及已完成归入的资源。管理后台仍要求管理员身份。迁移后撤销原访客对已转移内容的访问，旧链接、缓存URL和流式重连同样受限。

请求修改状态须有CSRF防护或等价的同源校验，错误中不泄露其他身份是否存在。客户端缓存按principal命名空间分隔；退出清除账户缓存并换成空访客空间，保留防重复发放标记及必要的未转入匿名钱包能力，不能自动再发100。

## 四 对话保存与用户控制

### F02 正常对话与临时对话

正常访客对话默认在服务端保存，并在IndexedDB缓存当前空间的消息和草稿；两者按最后活动起180天清理。界面显示到期规则，用户可提前删除和导出。缓存可能因浏览器清理或空间不足丢失，不承诺永久；删除同步到服务端，不能随后被旧缓存重新上传复活。缓存只存展示与恢复所需内容，不存账户口令、API密钥或权威账本。

用户在第一次发送前获知保存、IP安全用途和积分规则，并可改为临时对话。临时对话不保存正文、摘要、长期记忆或本机历史，不进入迁移；请求结束后丢弃过程内容，只保留费用、安全和必要去重元数据。临时对话仍扣实际积分，必须在切换时说明。

现有本机旧记录仅在用户同意后导入当前空间，以稳定记录ID去重，标记“本机导入”。不根据客户端内容创建赠送、已付账单或核验引用状态；旧消息不能伪造模型用量。临时旧记录不导入。导入失败保留原本机副本并可重试，成功后按新的归属权限访问。

### 数据期限

推荐普通访客内容闲置180天、产品反滥用原始IP明细30天、HMAC风险标识180天。最小积分账本和请求去重信息在相关额度到期且请求全部终结后继续保留180天，随后删除关联或转为不可逆汇总；如有适用法定义务，按批准的分类期限隔离处理。HMAC不是匿名化，盐轮换须兼顾有效去重期，密钥与业务数据隔离。

账户是否已接收访客余额的最小claim_used标记单列，在账户存续期保留，不随旧账清理重置；注销后的处理按批准策略执行，不承诺识别重新注册后的同一自然人。访客去重凭证不授予内容或钱包访问权；超出去重保存期或全部凭证被清除时，不能保证自然人层面永久识别，需结合补贴预算控制风险。

上述期限是产品默认值，不能替代适用法律。现行网络安全法对相关网络日志规定不少于六个月留存，部署前需识别这些日志并单独设置期限及访问权限；不能把所有对话正文都归为必须长期保留的安全日志。[网络安全法](https://www.cac.gov.cn/2025-12/29/c_1768735112911946.htm)

提供查看、导出、删除与注销入口，告知哪些最小账务及安全记录仍须保留、原因和期限。个人信息的用途、方式、类别、保存期限及权利渠道需清楚告知；上线审查具体处理依据及对外服务的数据流。[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

## 五 钱包与赠送规则

### F03 访客批次

访客额度按资格幂等发放一次100积分，批次expires_at为原始发放时刻加180天。换IP、刷新、失败重试、退出、注册或归入账户不续期、不补回已消费部分。资格判定采用第一方去重能力结合风险策略；清除所有凭证或跨设备后无法绝对识别同一自然人，产品不得宣传完全防刷。

### F06 每日批次

用户当天首次读取钱包或发起有效生成时，幂等发放当日100积分。唯一约束为user_id、benefit_date、benefit_type；benefit_date由服务端上海时间计算。未访问的日期不补发；定时任务只做补偿和清理，不能作为唯一发放来源。

所有发放入口调用同一补贴资格服务，包括读取钱包、生成起算、定时补偿与后台补发。benefit_pending时均先核验资格，不能从其他路由绕过；已正常核验的会员不因外部验证服务故障被重置待核验，每日100仍按既有资格幂等发放。新风险账户的待核验规则在注册前告知，平台暂停调用不得显示为用户余额已耗尽。

注册当天的每日100就是注册赠送，不另叠加“新用户100”。新账户首次接收访客余额时，可用额度为当日未消费赠送加访客未冻结余额；访客冻结额度另列。早注册与耗尽后注册的首日总权益相同，均最多拥有一次访客100与当日会员100。

### 消耗与到期

按实际expires_at最早的可用批次先冻结和消耗，日期相同以发放顺序及ID稳定排序。不能固定“每日额度永远先用”：若访客余额22时到期、每日余额24时到期，应先用访客余额。

到期时，未冻结剩余记入过期账本；原请求已冻结部分可完成原请求结算。到期后释放的未消费冻结部分立即归入原批次过期，不能回到可用余额，也不能挪成第二天赠送。退款或补偿必须引用原账目；原批次仍有效时可返原批次，已到期时不得伪装返入可用。平台承诺补偿的，另发独立有效期批次并注明原因，不修改旧账。

## 六 模型价格与用量归一化

### F04 计费桶

每个provider与gateway及billing_model建立显式适配，不从模型名称推定单价。当前网关别名deepseek-v4.1-flash需通过实际网关验证；不得把其他直连服务官方价格当成网关结算价。密钥保留在现有安全凭据设施，价格导出与审计不得含密钥。

| 标准桶 | 含义 | 避免重复计费的要求 |
| --- | --- | --- |
| input_uncached | 未缓存且实际计费的输入 | 不含已经分配至缓存读写的token |
| cache_read | 供应商缓存读取 | 已在prompt总数中时先拆分，不能叠加 |
| cache_write | 供应商缓存创建 | 按实际TTL和供应商口径拆分，不能与其他桶重叠 |
| billable_output | 实际计费输出 | reasoning等明细若已包含，不再次加算 |
| total_tokens | 用量统计 | 不作为第五个额外收费桶 |

DeepSeek文档中的prompt_tokens由命中和未命中组成，cached_tokens可能是命中字段的另一种表示；适配必须择一而非重复累计。[DeepSeek用量字段](https://api-docs.deepseek.com/api/create-chat-completion/)

Claude文档中的input_tokens与cache_read_input_tokens、cache_creation_input_tokens分列，总输入需按其语义组合。该例用于说明供应商差异，不要求首版接入Claude。每个适配器都要验证字段缺失、零、别名及缓存写入TTL语义。[Claude缓存说明](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

未知用量记unknown，不记0；供应商明确不支持的桶记unsupported并记录适配版本。缓存字段不支持且无法排除收费差异时，不能默认免费启用；需关闭该计费能力或暂停模型。使用详情同时保留供应商原始数值与标准桶及映射版本，原始记录不得包含请求正文。

### 价格版本

F05价格配置包含供应商、网关标识、显示模型、计费模型、币种、每百万token价格、缓存TTL桶、计费倍率、有效起止时间及状态。默认币种CNY、倍率1.0；首版用户价格与供应商配置价一致。支持外币时必须固定并记录该请求适用的人民币换算率和版本，不在结算时临时取未知汇率。

价格分草稿、校验通过、已发布、已停用。需校验非负价格、必要桶齐全、单位、时间无冲突、用量映射与演示账单。免费桶必须明确配置为0并说明依据，不用空值代替。发布不可覆盖旧版本，只对新报价生效；停用阻止新调用，已获授权的进行中请求按快照继续或按服务故障补偿。

供应商成本价、用户计费价及汇率均冻结在报价和调用记录中。后续服务加价应新增公布的用户价格版本，不改固定积分汇率。历史账单可据快照复算。密钥、供应商内部采购折扣和用户可见单价分权限显示。

### 费用边界

一次用户请求包含理解、规划、资料组织、写作、必要复核和有界修订等正常模型调用，其输入包括系统提示、历史、检索材料和工具结构。各标准桶token乘对应单价再除以1000000得到费用，全部正常调用汇总后换算积分。用户点“重新生成”属于新请求，重新报价；系统自动网络重试产生的重复调用成本由平台承担，不能把同一阶段多次重试都转给用户。

本地缓存、应用复用旧回答、供应商缓存分别处理。无新模型调用的查看或复用不扣分；供应商缓存按已发布缓存价收费。Firecrawl首版由平台承担，独立记录请求数量与实际已知费用，不伪造token；后续若收费须单独展示并授权，不能追溯扣款。

## 七 发送前预算与结算

### 报价与冻结

每个有效发送先取得quote_id，包含身份、议题、上下文摘要指纹、模型及价格快照、允许的调用图、各阶段最大输出、最高积分、有效期和条款版本。默认报价有效5分钟，用户改变内容、模型或回答预算时需重报。常规价格发布不改变有效已报价的快照；紧急停用可使尚未启动的报价失效，明确提示后重新授权，不静默改价。相同草稿重复打开报价不得扣分。

报价覆盖真实输入、允许的资料与工具结果上限以及全部后续正常调用；不预设缓存命中。token估计不可靠时必须使用经过验证的保守边界，无法建立边界的模型不能向访客开放。不能一律每轮冻结100积分，也不能只预估最终答案而漏掉理解和复核。

提交时在同一事务中校验身份、报价、可用额度、幂等键和并发限制，再冻结批次。初期每个principal和共享钱包最多一个生成请求；多标签页同时提交只能一个成功。每个call发出前再次验证剩余授权预算和请求状态，无预算不得发起下一阶段。不能为凑余额跳过安全或证据检查。

### 结算与幂等

按供应商请求ID、内部call_id和request_id记录已验证用量；幂等处理流尾、重连、回调及对账。一个请求最多产生一次最终用户扣账，后续纠错用冲正与新调整记录，不覆盖原账。正常完成后先结算再释放余量，余额投影与账本事务一致，崩溃重启可从持久状态恢复。

实际费用超过已授权上限时用户只承担上限以内金额，差额记平台承担并告警，不能负余额、借用次日赠送或隐性追扣。若因系统错误没有可恢复的有效回答，用户费用为0，已发生供应商费用记平台承担。客户端断网但普通回答已完整安全保存时，只结算一次并允许免费恢复；临时对话无法恢复时不宣称已保存，按未交付失败补偿。

### 主动停止和未知用量

用户停止后不启动新call，已经发出的call可能继续计费；只结算可核验的已发生用量，发送处事先简明告知。只取消输入或在模型调用前取消不扣分。反复中断不得通过虚构“系统失败”持续免费使用；风险措施不能制造无凭据扣款。

流式尾部缺失或usage不完整时进入usage_pending，不以估算值最终扣分。最多保留相关冻结24小时，按供应商请求ID查询或对账；期限内核实则按原授权结算，超时释放未结算部分，后到费用平台承担。新日额度不用于追扣。单钱包最多一个未结算生成，平台设置未结算总额熔断，避免缺失用量造成无限补贴。

模型上线门槛是实际网关在普通、缓存、流式、中断和多阶段路径中能稳定给出明确用量；连续缺失触发停用和告警，完成映射验证后恢复。用户余额不足和供应商不能计费是不同错误。

## 八 访客归入账户

### F07 资格与确认

注册或已有账户登录前预览当前空间议题数、可用和冻结额度。默认关联当前访客记录，用户可取消；登录成功不自动发送草稿或扣费。临时对话不参与。一个空间只能归入一个账户，一个匿名钱包只能转移一次，一个账户仅能接收一次访客额度。三个约束独立，不能合成一个guest_merged标记。

账户已经用过访客额度接收资格时，可以归入当前议题而不转移钱包。原匿名余额、冻结和原始期限继续保留在仅能操作该匿名钱包的受限恢复能力下；登录态只用账户积分。退出后以空内容空间使用原余额，不再读取已归入的内容；匿名账单仅保留不能反查内容的费用元数据，不展示已转移的标题、正文或结果链接。账户可读已承接结果，但不能因此操作未转入的匿名钱包。不能清空该余额，也不能为了补偿另发一份100。

### 事务和恢复

迁移锁定空间、钱包、账户资格及相关冻结，采用稳定钱包映射或平衡转账账目，把尚未消费的批次和进行中冻结一起接管。已消费额只保留历史，不再发放。先校验全部条件，再在事务中提交所有权与资格；前端只在committed后切换权威归属。账户当日赠送另按每日唯一键创建，不把它当迁移金额。

进行中旧请求沿reservation稳定ID结算一次，结算目标跟随钱包归属映射；完成迁移不重新调用模型。旧guest内容访问在提交时撤销，账户凭新权限重连。迁移过程中禁止新的相冲突请求；先前已发出的调用允许对账。需要多步存储操作时采用可恢复迁移任务，失败不出现两边都可花或两边都不可恢复。

状态为prepared、claiming、committed、retryable或aborted。幂等键绑定guest_workspace与目标账户，重复提交返回同一结果；另一账户竞争已被占用空间返回归属冲突，不泄露其数据。部分本机上传以topic_id、message_id去重，支持继续上传；完成前保留本机副本，取消后不标记成功。

### 具体数值

访客原100已花60，可用40；注册当日新发100，可用140。若访客已花60、可用20、冻结20，归入后可用120、冻结20；旧请求实际扣12.5后释放7.5，可用127.5，累计花72.5，总权益仍为200。访客余额原到期时间不因注册改变。

每日旧批次剩50，其中冻结40、可用10；午夜可用10过期并新发100。旧请求花32、释放8，释放部分随旧批次过期；新日仍可用100。冻结不是额外赠送，过期不能把冻结再扣两次。

## 九 页面与状态要求

聊天页公开可访问，显示访客或账户身份、可用额度、冻结中额度和最近到期时间。发送处展示本轮最高费用；按实际费用结算，较低余额可使用已验证简短路径。费用弹层显示用户价格、标准用量和精确扣分，主对话不插入冗长财务信息。

访客耗尽引导注册并说明当日赠送100；保存草稿，完成后返回原议题，由用户发送。会员不足显示明日00时赠送及现有记录入口。没有充值能力时不出现充值按钮。冻结中、用量待核实、风控验证、服务不可用和额度到期应分别显示。余额充足但预估上限不足时显示“本轮最多X，可用Y”，不称已耗尽。

积分页按批次展示来源、可用、冻结、到期时间及已过期；消费页展示request_id、时间、议题可选标题、模型、各桶用量、用户价格版本、扣分和异常补偿。删除议题后标题改为“已删除议题”，账单不保留正文。注册合并说明在提交前可键盘访问，屏幕阅读器可读，移动端不遮挡输入或取消按钮。

后台提供价格版本发布、供应商调用明细、钱包流水、每日补贴及异常面板。财务默认聚合看数据，不默认开放正文和完整IP。调账必须记录原因、操作者、原账引用；超过配置阈值须复核。导出脱敏并限制权限，密钥、Cookie及原始提示词不得进入费用日志。

建议复用现有路由和SSE机制扩展，下列是逻辑契约，不要求另建平行聊天服务。写接口均做身份校验和幂等处理，服务端时间为准。

| 接口 | 主要输入 | 主要输出与限制 |
| --- | --- | --- |
| POST /api/guest/bootstrap | 同源请求、能力校验 | 当前空间及资格状态，不因浏览发分 |
| GET /api/points/wallet | 当前principal | 批次、精确可用与冻结、下一赠送时间 |

| POST /api/agent/stream | quote_id、client_request_id、正文 | 请求ID、SSE状态、回答与结算通知 |
| GET /api/points/requests/{id} | 本身份请求ID | 运行状态、可恢复结果、最终或待结算账目 |
| POST /api/account/guest-claim | 登录授权、claim_id、当前空间、确认范围 | 迁移任务ID及提交状态，不自动生成回答 |

HTTP或结构化错误区分401身份过期、402额度不足、403验证失败或风险保护、409并发或幂等冲突、422报价或价格配置失效、429风险限速、503模型或验证服务不可用。风险错误只返回通用原因类别、risk_event_id及分档重试时间，不返回风险分数、剩余次数或命中阈值。不要将它们全跳转登录。所有limit与时间范围设服务端上限，导出分页或异步，避免新增DoS入口。

SSE事件包括accepted、progress、answer、usage_pending、settled、error及done，携带request_id和单调event_id。断线以同一请求恢复，不重发模型任务；浏览器没有收到done不能据此认定失败免费。取消、删除与迁移必须使用版本或令牌校验，旧客户端凭证和过期版本的晚到流不能越权写回；已登记的在途服务端请求可通过稳定映射完成新归属交付与结算。已删除的正文不得复活，最小费用结算仍独立处理。

## 十二 风险控制与非功能要求

### 安全边界与现状

本章所有安全控制为P0。按接口可以被查看、客户端代码和参数可被修改设计；服务端认证、授权、资格及账本才是安全边界。前端混淆、禁止调试、隐藏接口、客户端固定签名密钥、User Agent或设备指纹均不能单独防刷；同源、CSRF及CORS控制也不能证明真人。用户提示词、检索材料或模型工具调用不能签发赠送、调账、退款和价格变更；生成服务仅获得读取报价与提交已核验用量等必要权限。

现有AuthService有验证码短期与一次性校验、密码哈希、未知账户等价校验及失败锁定；HTTP层有请求体上限和部分进程内限流。现状缺口是：算术SVG包含可读取算式；HTTP登录注册未传入持久化来源限流参数；管理员登录未接入同等入口限流；自动失败冷却与管理员锁定共用locked_until，可能连带影响既有会话。这些都不能视为已有强反机器人能力，实施时先修正，再开放访客补贴。

### F08 登录防爆破与分层限流

登录同时检查账户维度和可信来源维度的独立计数，并增加第一方浏览器资格及全站入口容量限制。不能只设置“IP加用户名”组合，否则更换用户名或来源就形成新桶。无效挑战也计入来源和挑战限流；只有通过必要挑战后的真实凭据失败才累计账户失败档位，降低恶意锁号成本。

失败冷却、风险暂停和管理员封禁使用独立状态。失败冷却只约束新的认证尝试，不撤销已认证会话；已进入冷却后继续探测不能无限延长。正常成功或连续30分钟无失败可重置失败档位，管理员封禁仍按单独流程解除。登录响应不区分账户不存在、密码错误和被保护的账户，恢复与申诉入口也必须核验身份及限流。

验证码生成、外部验证、密码KDF、建账户、报价、模型与搜索调用之前分别执行廉价检查。所有计数及准入决定原子化，跨进程、跨实例和重启共享；SQLite可事务实现，扩容后可迁移至共享存储，不能仅用进程字典或前端倒计时。采用滑动窗口或令牌桶，窗口边界不能双倍突发；计数键数量、TTL、队列和外部验证并发都有上限，防止随机用户名撑爆计数表。

下面是内部推荐起点，均须配置化并按正常流量校准，不作为对外提示文案。来源及设备阈值主要触发升级验证；单身份、挑战尝试和全站资源硬上限不得被验证码通过绕过。

| 控制对象 | 推荐默认值 | 超限处理 |
| --- | --- | --- |
| 账户登录失败 | 同账户5分钟5次，先冷却60秒，连续异常逐级至15分钟 | 通用失败与分档重试，不踢已有会话 |
| 登录来源异常 | 同可信IP5分钟30次认证尝试 | 新或高风险会话升级挑战，结合全局容量限制 |
| 挑战签发 | 每第一方会话每分钟5次；每IP每分钟30次；同目的最多2个待用 | 限发和冷却，共享IP允许验证后的正常用户继续 |
| 挑战使用 | 业务有效期120秒；最多3次错误；一次性 | 失效后重新获取，旧挑战不恢复 |
| 批量注册信号 | 同浏览器24小时超过3个成功账户，或同IP1小时超过10个 | 进入补贴资格核验，不直接封整个IP |
| 报价请求 | 每principal每分钟20次 | 返回429，不发分、不调用模型 |
| 生成起算请求 | 访客每分钟6次，会员12次；每身份与钱包仅1个在途 | 拒绝新增任务，重连同一请求不新增生成 |
| 平台现金预算 | 80%告警，100%阻止新增未承诺支出 | 具体人民币日上限发布前配置，不默认无限 |

管理员入口单独限流且公网启用第二因素，建议TOTP或Passkey；密码正确不绕过风险判断。密码与第二因素校验均限尝试，恢复流程不得成为更弱入口。价格发布、积分调整、解除限制和安全配置修改要求近期重新认证，复用原有调账审计及复核要求。[OWASP认证建议](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)

### F09 人机验证与挑战防重放

首次访客领赠、注册及高风险操作须通过可由服务端验证的抗自动化挑战；低风险允许无感验证，正常聊天不逐轮弹交互验证码。可选供应商须验证生产地区可用性、无障碍能力和数据处理方式，本方案不锁定厂商。现有算术SVG不能作为强验证降级通道。

挑战由服务端绑定action、principal或预认证会话、business_operation_id、一次性nonce、预期站点及到期时间。服务端核验供应商响应的有效性和适用的站点、action及上下文，不信任客户端success字段、完成时间或自报身份。业务有效期采用120秒与供应商剩余有效期较短者；签发和校验都限速，最多3次错误后失效。

通过证明仅授权绑定的一项操作，消费证明与领赠、建账户或其他操作提交须具有原子及幂等关系。所有受保护操作的幂等键绑定规范化参数摘要，注册、领赠、迁移、调账同样适用；同ID不同参数必须拒绝，不能复用验证或近期认证证明授权另一项内容。并发重复使用只能一个新操作成功；同business_operation_id合法网络重试返回原结果，不能因此让证明可用于另一笔赠送。供应商验证超时后先查询原操作状态或重新挑战，不将未知结果当通过。验证供应商的幂等重试参数也不能替代业务账本唯一约束。

以Turnstile为例，官方要求后台验证，token有有效期且只能验证一次；前端挂载组件不能独立证明完成验证。实际接入仍须按所选供应商语义实现和测试。[服务端验证说明](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)

### F10 赠送资格与账户工厂防护

第一方试用资格、账户接收标记、每日唯一键、风险状态与人机证明共同控制新增补贴。注册成功后，正常资格自动发当日100；命中批量异常时先标记benefit_pending而非假发后清空。验证通过后仅发当日尚未领的一笔，不补历史日期。查看已有账户记录的权限不能因补贴资格待核验被扩大或转给他人。

账户或访客换IP、换User Agent、轮换workspace、清理缓存和更换客户端请求ID都不能直接重置已知的领赠资格。IP地址归一化，IPv4映射地址及等价IPv6文本不能形成多个来源计数；IPv6前缀、代理、ASN和设备行为仅作辅助风险信号。只信任配置的代理链，任意转发头无权选择风控来源。

共享网络不能仅因累计人数触发全IP永久封禁。升级验证、短暂降速和人工申诉优先；规则不能只因VPN、无痕模式、键盘操作、辅助技术或无头标记判为恶意。默认仅用第一方随机标记及必要粗粒度信号，不收集Canvas、字体等高侵入指纹或精细输入轨迹；不为体验额度默认要求实名或手机号。清除所有凭证、不同设备及账户重建后，无法完全识别同一自然人，损失上界仍由现金预算控制。

### F11 防篡改与补偿套利

客户端余额、积分增减、时间、benefit_date、价格、token数、currency、供应商usage、失败和退款标志均为不可信输入。业务接口采用允许字段列表；服务器从身份、价格快照和已核验供应商响应重建依据，拒绝或忽略越权字段，不能因请求中夹带正数、负数、溢出或重复字段改变账本。日期完全由服务端决定。

quote_id绑定当前身份、内容、模型、有效期和授权预算；client_request_id在所属身份下唯一，同键不同正文或模型拒绝。领取、每日发放、迁移、冻结、结算、释放、退款和补偿都有独立业务唯一键；只能从允许状态转换，不能跳过冻结直接结算或先释放后再次花费。数据库约束及事务保证多实例竞争下不重复发放、双花、负余额或转移在途冻结。

供应商usage只能来自服务端持有凭据的调用或经过验证的回调；如启用回调必须验签、检查时效并去重。客户端主动断网不等于系统失败，停止后按已核验用量处理；不得用客户端“没收到”报告触发自动补偿。系统事故由服务端交付状态、原账及事故ID判定，一次补偿一个原账，重试不再领。临时对话未交付与用量缺失继续按第七章处理，同时受请求频率、待结算数量及现金预算约束，不能以异常分支绕开费用上限。

### F12 现金预算与运营闭环

现金预算独立于用户积分账本，按供应商人民币成本上界计量，覆盖正常赠送消耗、平台承担的重试与失败、未知用量、搜索和超授权差额。请求准入先冻结全部有界成本，每次模型或搜索call派发前原子核验“该预算日已发生金额加尚未释放的成本承诺”不超上限。请求承诺与子调用承诺是父子分配，不重复累加；实际用量结算后才释放差额。可查询原回答的重连不新增承诺。

达到80%告警，达到100%仅允许已承诺范围内且可核验预算的调用，阻止扩大新支出；系统自动重试同样占用现金预算。午夜不重置在途承诺：已派发及unknown子调用留在原预算日；跨日新派发前先核验新日容量，在同一事务转移相关未派发承诺，提交成功前不得释放旧日承诺。新日容量不足时禁止派发，安全终结或保留原承诺等待恢复，不先释放再调用。用户积分因未知用量24小时释放时，供应商未核实成本仍以保守承诺或明确标记估计成本计入运营上界，不能借此无限释放平台预算。

现金预算约束系统能够核实的授权上界，供应商侧可用费用限额和告警补充兜底。费率异常、估算偏差或迟到账单导致实际费用超出承诺时，立即停新调用并对账，差额由平台承担，不能宣称外部账单绝无超支风险。

风险或验证服务故障时，新赠送资格及不能安全授权的高成本请求暂停，已有余额不清空、记录按原权限可管理。可验证的低风险存量请求仅在现有硬预算内继续，不跳过所需挑战；返回明确服务状态和重试路径。全局预算熔断、人工放行或验证通过都不能突破账本不变量，不能将平台超支转成用户欠费。

后台记录risk_event_id、动作、规则版本、决定类别、时间、限定标识摘要和关联业务ID；对默认财务视图脱敏，禁止记录密码、完整凭证、挑战答案、模型密钥或正文。提供挑战失败率、来源异常、补贴资格核验、现金承诺、额外平台成本和误伤申诉指标；超过容量立即告警，安全阈值配置变更可审计及回滚。风险事件沿第四章分类期限保存，不因新增风控默认无限留存。

安全规则按领取、注册、赠送、迁移、生成、退款与补偿的完整业务流程评审，不能只验证单个接口有登录。推荐先以影子判定观察误伤，再对新增补贴分批启用；金额、授权和幂等硬约束始终生效。[OWASP敏感业务流程防滥用](https://api-security.owasp.org/editions/2023/en/0xa6-unrestricted-access-to-sensitive-business-flows/)

### 可靠性与性能

钱包和迁移写操作必须事务化；SQLite实现需考虑写锁、繁忙重试及多进程一致性，不能仅依靠进程内锁。进程重启后可恢复冻结和迁移任务；后台清理与在线结算同样幂等。服务故障时关闭新付费调用，仍允许查看和管理已有记录。

建议性能目标为钱包读取P95不超过300毫秒、报价本地计算P95不超过500毫秒、提交冻结P95不超过500毫秒，均不含外部模型、搜索或人机验证时延；先在约定硬件和并发负载下建立基线再确认。账本金额误差、重复赠送、重复扣账、跨身份泄露和负余额必须为0，不能以性能为由放宽。

## 十五 交付顺序与上线门槛

第一阶段先修正现有认证与验证码缺口，完成供应商适配验证、价格快照、账本和积分及现金冻结状态机，使用隔离数据验证全部金额和并发不变量。第二阶段统一guest和user授权，完成人机挑战、访客保存、每日发放、归入账户及删除恢复。第三阶段完成账户工厂识别、管理报表、对账、补贴熔断、误伤申诉和小流量真实网关验证。

发布前必须具备：A01至A66通过；目标网关真实用量语义和价格有可复核依据；默认100积分可完成标准体验；人机验证及管理员第二因素可用；有限的现金预算、值班告警和异常回滚可用；数据告知及日志配置完成部署审查。回滚应停新调用并保留账本、余额和迁移记录，不以删除数据恢复旧版。

观察指标包括首次有效回答完成率、注册后原议题继续率、迁移成功率、每名访客补贴、缓存实际节省、用量完整率、冻结超时、重复账目和不变量差异。用户有无获得帮助仍以问题理解、建议可行性及后续反馈评估，不能只看消耗或转化。

**尚待上线确认的配置。** 网关实际单价及字段映射、供应商对账能力、全站每日补贴上限、支持的最低预算路径、保留期限与生产代理链。本文给出推荐值和验收方法，配置未核实前不启用对用户正式扣分。
