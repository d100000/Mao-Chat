# 教员：以史料方法理解困惑的对话助手

工作台默认进入 `consult`（对话解惑）模式。用户可以直接描述困惑，不需要先知道某句语录或篇名。助手先理解处境、想达到的目标、现实限制与已经尝试过的方法，再检索本地核验资料，解释可以借鉴的方法及适用边界，在用户需要建议时，提出可撤回、可观察结果的下一步。用户只想倾诉时，先倾听，不安排任务。

这个过程可以是多轮的。信息不足时，只追问最影响判断的一两个问题，并先回应当前能理解的部分；用户补充或纠正事实后，助手应更新分析，而不是继续重复旧问题或固守上一轮建议。“我的理解”是待用户确认的工作假设，不是系统已查证的用户事实。

## 一段典型对话

1. 用户先描述：“最近工作很累，几个方向都有人催，不知道先做哪个。”
2. 助手确认卡点，询问真正想达到的结果和眼下最硬的限制。
3. 用户补充：“两个人、六周期限、没有额外预算，先保住现有客户。”
4. 助手使用调查研究、具体矛盾、实践检验等相关核验资料，说明为何先辨别客户的真实问题，再提出本周的小实验、观察信号和复盘条件。
5. 用户反馈实验结果，助手据此调整建议，并说明哪些事实和判断发生了变化。

建议是今天根据用户处境提出的现代应用，不冒充毛泽东本人建议。历史政治、战争或组织实践不能直接等同于今天的工作和人际关系。资料不足时，应承认缺口；没有对应历史事件或逐字资格时，不编造故事或名言。

## 四种对话范围

| 模式 | 用途 |
| --- | --- |
| `consult` | 默认：围绕用户困惑理解目标、综合分析和持续复盘。 |
| `research` | 原文、语句、版本和历史背景的研究问答。 |
| `historical` | 按明确截止日期使用当时可用资料的历史情境。 |
| `modern` | 已明确问题时，将史料方法转化为今天的具体建议。 |

默认界面突出对话，其他模式收在“更多模式”中。“对话笔记”的“理解”页分别展示长期方向、阶段目标、本轮诉求，以及处境、限制与尚未确认事项；“行动”页可确认建议并记录反馈；“依据”页区分本轮实际引用与其他检索资料。点击回答中的引用可查看出处和适用范围。来源状态与用户自述是两种不同的信息，不能混为历史事实。

## 议题、行动与记忆

侧栏可继续议题、修改标题、归档、导出或删除。归档保留记录；删除清除当前账户该议题的会话、引用、运行记录与派生状态，且阻止尚在生成的回答把它重新保存。已导出的副本、其他议题中已有的内容和外部服务商的数据不在这次删除范围。

模型只提出行动建议，初始状态为“待确认”。只有用户操作才能改为已采纳、已尝试、已复盘或停止；请求缩短回答不等于完成行动。反馈会成为后续复盘的上下文。

用户可把某个议题设为可供记忆，之后在新对话中主动选择最多三个议题作为背景。系统显示使用了哪些议题，并把旧理解标记为待确认，不能当作新事实。关闭授权后，该议题不可再选为记忆。

“临时对话”不保存本次历史到应用数据库、会话文件或浏览器本地记录。用户仍可显式选用已授权的旧议题；该次使用不更新原议题。模型及已开启的搜索服务仍会处理发送内容，临时状态不承诺服务商不留存。

## 资料初始化

公开仓库可直接运行：

```bash
python3 scripts/bootstrap_library.py
```

初始化导入37条核验资料、哲学规则、事件关系、FTS 和离线向量。完整 PDF、OCR 与全文页索引是可选本地资产；公开版本仍支持核验卡检索和对话解惑，无法据此进行完整逐页全文搜索。已有库不会被默认覆盖；更新资料时明确使用 `--refresh-library`，保留账户等私有表。

准备好本地全文资产后，可按 [全文资料说明](../corpus/README.md) 重建：

```bash
python3 -m agent init-db
python3 -m agent ingest
python3 -m agent index
python3 -m agent vector-index
python3 -m agent doctor
```

全文库的页数与向量数以本机 `doctor` 结果为准。OCR 仍需在直接引语时回看原 PDF；离线向量是可重复的检索基线，不等同于语义 embedding 模型。

## 配置模型

复制 `agent/config.example.json` 为 `agent/config.json`，修改 `base_url`、`model` 和参数。密钥优先从环境变量读取；macOS 也可以使用配置中的 Keychain service。支持兼容 Chat Completions 的网关；公开仓库仅提供配置示例，不包含可用凭据。

```bash
python3 -m agent --config agent/config.json doctor
```

输出只显示密钥是否存在，不显示密钥本身。

## 流式问答

直接从困惑开始（CLI 默认 `consult`，也可明确指定）：

```bash
python3 -m agent ask \
  '我带着一个两人的项目，六周内要上线，几个方向都有人催，怎么选重点？' \
  --mode consult --session my-project
python3 -m agent ask \
  '补充一下：现有客户更在意稳定性，我想先保住他们。请据此调整建议。' \
  --mode consult --session my-project
```

原文研究仍然可用：

```bash
python3 -m agent --config agent/config.json ask \
  '请查找1938年反对亡国论和速胜论的原篇、事件背景和哲学方法。' \
  --mode research
```

历史人物模拟必须给截止日期：

```bash
python3 -m agent --config agent/config.json ask \
  '为什么反对亡国论和速胜论？' \
  --mode historical --as-of 1938-06-30
```

`thinking`、`reasoning_effort` 和 SSE 流式输出会发送给兼容网关。`--show-reasoning` 只显示网关实际返回的 reasoning 字段；网关不返回时不会伪造思考内容。

多轮会话：

```bash
python3 -m agent --config agent/config.json ask \
  '先解释这两个论断。' --mode research --session demo
python3 -m agent --config agent/config.json ask \
  '继续拆解客观条件和实践检验。' --mode research --session demo
```

会话模式和历史截止日期固定，切换时使用新的 session ID。会话保存用户问题、最终回答，以及供恢复用的暂定理解与证据元数据，不保存密钥。不同账户的浏览器缓存相互隔离。

`consult` 中的 `understand_user` 工具记录暂定理解，并可通过 `analysis` 事件展示给界面；`method_search` 检索已有核验卡、方法概括、符合核验条件的公开事件，以及12个有出处的思想解释维度。思想解释只有在关联原著卡仍通过核验时才可用；它保留原作条件与现代迁移边界，不获得原话资格。方法概括不等于原话，事件缺口也不会因为主题相似而被自动补成语录—事件关系。

解惑回答在展示前还会复核一次：对照用户原话和待确认事项，删除自行补出的时间、人数、动机或选项关系，再运行引用检查。复核计入工具循环的步数上限，不会无限重试；它用于减少细节漂移，不能替代用户核对或保证模型判断总是正确。

后续回答沿用前轮证据时，系统会按证据 ID 精确回查已核资料库，并把返回的来源记录进本轮引用。查不到、未核验或仅有事件关联字段的条目，不会自动获得原著引语资格。

## 搜索和追溯

```bash
python3 -m agent search '论持久战 速胜论' --kind passages --limit 5
python3 -m agent vector-search '实践如何检验认识' --limit 5
python3 -m agent trace-quote '矫枉必须过正'
python3 -m agent trace-event '1938'
python3 -m agent trace-page 02_selected_works_v2:p0111 --context 1
python3 -m agent --config agent/config.json web-search '毛泽东 论持久战 官方原文' --limit 3
```

命令行网页检索可保存到 `web_sources`，并标记为 `untrusted`；浏览器请求不写共享网页缓存，持久议题只保留本账户的候选来源，临时对话不保留。网页内容只能作为候选出处，不能覆盖本地核验资料或直接改变历史模式的知识范围。

## 验证与测试

运行 `python3 -m unittest discover -q` 检查模型循环、检索、史料资格、日期边界、会话、认证、管理员配置与前端行为。完整浏览器回归和真实模型验收见 [`e2e_usage.md`](e2e_usage.md)，测试数量与结果以本次运行报告为准。

解惑模式的真实验收覆盖模糊困惑的澄清、补充条件后的有据建议、目标纠正与实践反馈后的调整、恢复对话后继续复盘，以及旧研究模式回归。真实模型输出的语义质量仍需要阅读保存的回答检查；通过 HTTP/SSE 或非空断言，不等于已经证明建议适合所有用户。

真实远程服务的可见 reasoning 由网关响应决定，不能把一次测试结果推广为所有请求都返回 reasoning 文本。

本次发布的可复现自动检查与有限真实模型验收记录在 [发布验证记录](release-validation.json)。自动流程覆盖不等于长期陪伴效果得到验证；真实回复仍需结合具体场景评阅。
