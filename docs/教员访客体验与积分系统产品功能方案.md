# 教员访客体验与积分系统产品功能方案

产品评审稿  版本 1.1  2026年10月27日

本文面向产品负责人、设计师、运营和研发负责人，定义“免登录开始对话—按模型消耗使用积分—注册后继续聊”的完整体验。建议保留教员的持续对话主线，把积分作为透明的使用额度，避免用户先理解复杂计费才能表达困惑。配套《教员积分计费系统产品需求文档》规定账务、接口、异常和验收要求。

**交付性质。** 本文是功能设计和实施依据，不代表积分系统已经开发或通过测试。用户明确的业务要求与本方案补充的推荐默认值分别列明；推荐值可在研发评审时调整，但必须同步修改配套需求文档及验收标准。

## 一 目标与范围

教员通过持续对话理解用户的困惑、目标和现实限制，参考毛泽东原著与经核验的历史材料提供有依据的分析。免登录体验降低首次表达的门槛；积分限制平台补贴、解释模型消耗，并让用户知道还能否继续。积分多少不能影响引用核验、安全回应或对用户的尊重。

首版实现访客对话、一次性体验金、会员每日赠送、模型计费、消费明细、访客记录归入账户和后台核算。用户所说的“兑换”已明确为“继续对话”；首版不包含兑换码、充值、支付、提现、积分转赠或积分交易。

| 用户已确认的要求 | 产品规则 |
| --- | --- |
| 不登录也能对话 | 公开聊天入口直接可用，首次发送前完成必要告知 |
| 访客只能使用100积分 | 每个符合条件的访客资格一次性获得100积分，不按日重发 |
| 一毛钱等于100积分 | 固定换算为1元等于1000积分，1积分等于0.001元 |
| 按模型费用统计与扣分 | 服务端记录各类计费token和单价，按本轮实际费用结算 |
| 注册后每天100积分 | 上海时区每天发放一次，当日未消费部分到期失效 |
| 耗尽后注册继续聊 | 注册当日获得当天100积分，当前访客议题可归入账户 |

## 二 推荐默认规则

以下是为消除实施歧义补充的默认值，属于方案建议，尚未成为已上线承诺。费用换算由用户确定，不在本表调整。

| 项目 | 推荐默认值 | 用户能感知的结果 |
| --- | --- | --- |
| 访客额度有效期 | 首次成功领取起180天，固定到期 | 不是永久余额，访问或注册不延长 |
| 每日赠送日期 | Asia/Shanghai自然日 | 每日00时切换，不要求签到 |
| 注册赠送 | 注册当日的每日100积分 | 不再叠加另一笔注册100积分 |
| 访客余额归入 | 每个账户存续期一次，每个访客钱包一次 | 仅转移尚未使用的额度，保留原有效期 |
| 扣减顺序 | 按各批次实际到期时间先后 | 先使用最早到期的积分 |
| 正常对话保存 | 本机缓存和服务端访客记录，闲置180天后删除 | 可在同一浏览器继续；本机缓存可能被清理 |
| 单次使用上限 | 发送前给出本轮最高扣分 | 最终按实际结算，不超过授权上限 |
| 搜索费用 | 首版由平台承担并独立统计 | Firecrawl费用不混入token积分 |

“长期缓存”应表述为有期限、可管理的保存。访客的恢复凭证丢失后，不能凭IP找回记录；跨设备可靠保存需要账户。IP用于识别异常使用，不用于判定谁拥有对话或积分。

## 三 从第一次对话到持续使用

### 首次进入

用户进入聊天页即可看到输入框和“访客体验100积分”说明，不先弹出登录拦截。输入框附近简短提示：教员是参考毛泽东原著与公开史料的AI问答助手，用户可以从一件具体困惑开始。首次发送前明确说明对话保存方式、IP用于安全防护以及积分规则，并提供临时对话入口。

仅浏览页面不领取、不扣分。第一条通过格式和风险检查的有效请求触发访客资格检查及一次性发放。发放成功但模型服务暂不可用时，100积分保留；不因为刷新、失败重试或更换IP重复发放。IP相同的不同用户不能被直接视为同一个人。

### 发送与回答

积分区域展示“可用”“本轮冻结”和最近到期额度。发送前根据真实上下文、模型和回答预算计算本轮最高扣分。按钮旁显示例如“本轮最多20积分，按实际消耗结算”；授权仅覆盖这一轮，价格或上限提高时必须重新确认。

正常路径是输入困惑、发送、看到理解或检索进度、收到回答、看到实际扣分及依据。用户无需逐项确认内部推理步骤。所有正常模型调用都计入本轮，包括理解、资料组织、写作及必要复核；隐藏上下文也会消耗token。费用详情提供展开查看，主聊天页保持简洁。

回答应保留原有的事实核验和引用要求。系统可以给出预算可支持的简短回答，但不能为了省积分跳过证据或安全检查。如果当前模型不能在100积分内完成至少一条标准体验路径，不得将它作为默认访客模型。

### 余额不足

“不足以覆盖本轮最高费用”与“余额为零”分开显示。尚有少量积分时，优先提供经过验证、预算更低的简短回答选项；没有可行方案时，解释预计上限和当前余额。不得暗示余额已经全部用完，也不得先扣成负数再要求补足。

访客耗尽时保留输入草稿和当前议题，提示“本次访客体验额度已用完。注册后今天可获100积分，继续这个话题”。点击后打开注册流程，成功返回原议题；草稿继续保留，由用户主动发送，避免注册完成后自动生成并扣费。

会员当日额度用完时显示下一次发放时间，允许继续查看、导出和删除已有记录。首版没有付费充值入口，不展示无法兑现的购买引导。服务故障、额度冻结中和风控限制应各自解释，不统一包装为余额不足。

### 每日回来

会员当天第一次进入积分页或发起有效请求时，系统自动补发当日额度；不依赖用户签到，也不因定时任务失败漏发。隔日未访问不补发历史额度。凌晨前未消费的当日赠送失效，不累计到下一天；跨午夜仍在处理的本轮冻结额度按原批次完成结算。

## 四 注册和记录归入

注册和已有账户登录都可以承接当前访客议题。登录前展示“当前浏览器有X个议题、Y积分可用、Z积分冻结，可归入本账户”，提供继续归入与本次不归入的选择。默认承接当前访客空间，避免要求用户逐条搬运；共享电脑上允许取消关联。

记录归属与赠送资格必须独立。一个访客空间只能归入一个账户；账户是否已接收过访客余额，不影响它接收当前访客议题。归入后，原访客凭证不能再读取已转移的对话。只处理当前访客空间，不扫描浏览器里其他账户的缓存。

| 注册前状态 | 注册当日归入后的状态 |
| --- | --- |
| 已花60，剩40，无处理中请求 | 当日100加访客剩余40，可用140 |
| 已花100，余额0 | 当日可用100，原话题继续 |
| 已花60，可用20，冻结20 | 当日可用120、冻结20；旧请求只结算一次 |
| 账户已经接收过一次访客余额 | 可归入话题，不再转入第二份访客额度 |

最后一种情况下不能悄悄清空原访客钱包。未转入的原匿名余额及有效期保留在受限恢复凭证下，登录状态只使用账户额度；退出后可在新的空访客空间继续使用原匿名余额。已经归入账户的历史不会重新开放给访客，匿名账单也不能透露其议题标题或正文。界面解释本次哪些记录和额度已归入、哪些没有。

退出登录时清理当前账户的本机数据并撤销访问，保留防重复领取标记及仍有效的匿名钱包恢复能力；不能因为退出或换IP再次赠送100积分。清理浏览器全部数据会影响恢复，产品如实说明这一边界。

## 五 积分和费用如何解释

积分是平台提供的使用额度，首版不可提现、交易或转赠。人民币数额表示费用换算口径，不承诺可兑付现金。供应商成本价和用户计费价分开保存；首版建议两者一致、计费倍率为1，后续如有服务加价必须公布新价格，不能偷偷改变积分汇率。

后台为每个网关和计费模型设置未缓存输入、缓存读取、缓存写入及输出价格。缓存写入有不同有效期时分别配置。输入总数中的缓存命中不能再重复收费；推理token如果已包括在输出中也不能再次相加。实际接入的是网关别名deepseek-v4.1-flash，结算价格必须来自该网关的有效配置与账单，不能直接套用另一家服务的官方价。

**演示价格。** 假设未缓存输入每百万token为2元，缓存读取0.5元，输出8元。本轮输入20000，其中缓存命中8000，输出2000，费用为0.024加0.004加0.016，合计0.044元，扣44积分。这些数字只解释算法，不代表当前网关实际单价。

不设置每轮至少扣1积分。内部积分保留六位小数，按整轮费用仅向上舍入一次；例如0.0004元为0.4积分。余额主界面向下显示两位，极小正余额显示“低于0.01积分”，可展开查看精确值。浏览历史、本机缓存命中和原回答重看均不收费；供应商的缓存token是否收费取决于该模型已发布价格。

用户账单显示时间、议题、本轮状态、模型、输入和缓存及输出用量、单价版本、最终积分、冻结释放和异常补偿。供应商私有采购折扣不必对用户公开，但用户计费依据必须可追溯。已发布的历史价格不能被后台编辑覆盖；常规调价不改变有效期内已取得的报价。后台分开记录供应商成本、用户计费及舍入差额，不用积分折算值强行平采购账。

## 六 失败和中断的体验

发送前先冻结额度，回答完成后按已确认用量扣除，再释放余量。冻结不是扣费，用户可以清楚看到差别。系统失败且没有可恢复的有效回答，本轮用户扣费为0，供应商已发生的费用由平台承担。

普通对话的完整回答已经保存，但网络断开时，重连恢复同一结果，不重复调用或扣分。用户主动停止时，只结算已实际发生且可核验的费用，停止后不再启动新调用；被发出的调用可能仍产生费用，发送前应简要说明。临时对话没有可恢复结果时按失败处理，不能以“已经保存”作为扣费理由。

供应商暂未返回用量时显示“等待结算”，最多冻结24小时；到期仍不能核实则释放未结算额度，后到费用由平台承担。持续缺失用量的模型暂停积分服务并告警，不能靠估算持续扣分。用户删掉对话不会取消已发生的有效消费，也不会把正文复制进账单。

## 七 前台和后台功能

前台需要统一的积分入口：聊天页额度提示、额度详情、消费明细及到期说明。资料引用、理解修正、建议复盘等原有功能仍围绕同一议题工作。移动端在输入区附近提供简短额度信息，避免遮住输入框；状态不能只靠颜色区分，键盘和读屏可完成注册及继续流程。

后台分为模型价格、调用用量、积分账本、补贴与异常四类页面。价格支持草稿、校验、发布和停用，发布前展示生效时间及示例费用。用量按模型、日期、身份类型、调用阶段和状态筛选，分别看供应商费用、用户扣分、平台承担、未结算和对账差异。

后台应能回答“100积分支持多少真实体验、每天补贴多少、缓存是否生效、哪些模型用量缺失、是否重复赠送或扣费”。首版积分均为赠送，扣分仅表示额度消耗，不是现金收入；供应商账单由平台支付，正常体验补贴与失败、重试、超限等额外成本分别统计。财务视图默认不展示聊天正文或完整IP；管理员调账须有原因和审计记录，不能直接改余额数字或删除账本。

## 八 数据和用户信任

正常访客记录采用服务端授权保存与本机缓存配合，缓存不是账本。身份由服务端签发的第一方安全凭证识别；本机可见的余额只作展示。IP只用于安全和滥用分析，不能恢复聊天、合并账户或证明同一个人，也不发送给模型。公司、校园和家庭共享网络要允许正常使用，异常时采用限速、验证码与补贴总预算等分级措施。

建议原始反滥用IP明细保存30天，受控HMAC风险标识180天。它们仍可能关联个人，不称为匿名数据。上述是产品默认值，不能替代适用的法定网络安全日志要求；相关安全日志应按实际部署隔离保存。网络安全法对相关网络日志规定不少于六个月的留存要求，不等于所有聊天正文必须同样保留。[网络安全法](https://www.cac.gov.cn/2025-12/29/c_1768735112911946.htm)

正常访客内容默认闲置180天清理，用户可提前删除。临时对话不保存正文、摘要或长期记忆，也不进入注册迁移；只保留必要的费用与安全元数据。用户可查看各类数据用途、期限和删除方式；删除聊天与最小账务、安全记录的保留分开说明。个人信息处理应遵循明确告知和必要期限等要求，正式上线需结合部署审查具体处理依据。[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

## 九 防爆破与防刷积分

### 保护目标与现状

本次新增安全设计保护登录账户、赠送资格和平台模型预算。前端页面与接口可能被查看和自动调用，额度发放、日期、单价、用量、退款和余额均由服务端决定。修改本机数据、复制请求或让模型声称“已赠送积分”，都不能改变钱包。禁止调试、隐藏接口和前端代码混淆不作为积分安全措施。

现有代码已有密码哈希、验证码有效期及一次性消费、账户失败锁定和部分请求限流。仍需优先修正：算术SVG中可直接读取算式，不能作为强机器人防护；HTTP登录注册未接入持久化IP限流参数；管理员入口缺少同等入口限流；失败冷却与管理封禁共用状态，可能影响已登录用户。以下为待开发的新增要求。

### 分层防护与用户体验

正常用户直接进入对话，不要求每轮解复杂验证码。首次领取访客赠送、注册和高风险操作经过服务端验证的人机挑战；低风险可采用无感验证，出现异常才升级为交互验证、冷却或人工复核。验证码只能增加自动化成本，不能代替领赠唯一约束和成本预算。[OWASP认证建议](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)

| 保护环节 | 主要控制 | 正常用户的处理方式 |
| --- | --- | --- |
| 登录与管理入口 | 账户和来源独立限流，渐进冷却，管理员第二因素 | 显示通用重试说明，不因他人输错踢掉已有会话 |
| 验证码与机器人 | 挑战短期一次性，绑定本身份、本操作，后台验证 | 常规聊天不反复打断，过期可刷新，失败保留草稿 |
| 批量注册与领赠 | 第一方资格、多账户异常信号、领赠幂等与预算 | 共享IP不直接封禁，异常先验证并可申诉 |
| 消费与补偿 | 服务端价格及用量，冻结结算，防重放和并发双花 | 重连恢复原结果，不因刷新多扣或多领 |
| 平台费用 | 每轮及每次调用都有预算，异常支出熔断 | 停止新支出时说明服务状态，保留记录及原余额 |

登录失败冷却建议从同一账户5分钟内失败5次、冷却60秒开始，连续异常逐级延长，最长15分钟。账户维度和来源维度独立计数，不能仅限制“IP加用户名”组合。验证码、密码校验、建账户、报价和模型调用之前分别设限，避免攻击先消耗服务器再被拦截。

注册后每日100积分仍按正常账户发放。异常批量注册进入补贴资格待核验，验证通过后发放当日尚未领取的一笔100，不叠加、不补历史天数。IP变化、VPN、无痕模式或清缓存均不等于新的合法赠送资格；同IP多人也不等于恶意账户。浏览器标记会丢失或被复制，因此只能提高刷取成本，不能宣称绝对识别每个自然人。

人机挑战的服务端结果与业务操作绑定，一次通过不能用于另一个账户或另一次赠送。第三方验证不可用时，不默认验证成功；新增补贴或未经授权的高成本请求暂停，已有记录仍可在原权限内查看和管理。提供刷新、稍后再试和人工帮助入口，不清空草稿或积分。

### 防止逆向后绕过积分规则

客户端不持有可签发余额的密钥，模型密钥只在服务端。服务端只接受有效报价、当前身份和幂等请求ID；客户端上报的扣分、模型用量、成功失败或时间均不能直接入账。领取、每日赠送、迁移、冻结、扣分及补偿都有唯一操作记录，多标签和多实例竞争也只能完成一次。

用户主动断网不等于平台失败，客户端声称“没收到”不能自动领补偿。已保存的普通回答按原请求恢复并结算；确有系统故障按原账冲正或专项补偿，同一事故不能反复领。未知用量仍沿用24小时规则，同时限制后续调用，防止利用缺失账单连续免费生成。

平台现金预算与用户积分分开控制，预算覆盖正常赠送、搜索、系统重试、失败、超限及待结算的费用承诺。建议使用率80%告警，达到100%停止扩大新支出。具体人民币上限由运营设置，不能默认无限；暂停期间不删除已发额度，不改成用户欠费。

### 运营与误伤处理

后台增加风险事件、验证码失败、账户异常、预算占用和规则版本视图；对外只显示原因类别和大致重试时间，不暴露命中阈值或完整风险画像。配置修改、解除限制和积分调整都记录操作者及原因，敏感操作要求近期验证。公网管理员入口启用第二因素，优先采用TOTP或Passkey等独立验证。

设备与IP只作辅助信号，不默认采集Canvas、字体等高侵入指纹，不记录输入内容或精细键鼠轨迹来证明“真人”。误伤可重试、验证或申诉；风险解除不额外赠送。防刷覆盖完整业务链，而不是只检查单个接口是否登录。[OWASP敏感业务流程防滥用](https://api-security.owasp.org/editions/2023/en/0xa6-unrestricted-access-to-sensitive-business-flows/)

## 十 实施顺序与效果验证

先修正现有登录、验证码和管理入口缺口，建立可靠用量适配、价格版本、不可重复账本及现金预算，再开放访客入口。第二步完成访客资格、服务端记录、本机缓存及注册迁移。第三步补齐会员每日赠送、价格后台和可解释账单，将人机挑战、批量注册及补偿套利一并验收后小流量开放。

推荐按“计费不重复、赠送不重复、余额不为负、归属不串号、用量可核验”作为上线硬门槛。体验观察首次有效回答完成率、注册后续聊成功率、迁移成功率、每名访客真实补贴、冻结超时率及投诉原因；指标按试运行基线校准，不把注册率当成回答有帮助的替代指标。

上线前需确认四项运营配置：实际网关价格与用量语义、每日补贴总预算、访客试用及保存期限、真实部署下的数据告知与安全日志方案。现有功能、测试数量或以往模型实测不能代替本次积分系统验收。
