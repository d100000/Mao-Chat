# 从人物文本构建有史料依据的对话 skill

调研日期：2026年10月25日。

适用对象是由原著、语录、书信、讲话记录、回忆录等资料构建的人物对话系统。对本项目，首选方案是“可追溯文本库 + 按年代和证据类型过滤的检索 + 分阶段人物规则 + 引文核对”。人物口吻可以最后加入。单靠几条名言和一段人格提示，难以保证历史经历、思想变化和具体回答的一致性。

下文的系统结构、字段、流程和验收门槛是针对本项目提出的工程设计；论文实验结果只支持各自测试范围，不能直接当作本项目已经达到的效果。

## 研究依据与适用范围

| 主来源 | 已核验的方法或发现 | 本项目可借鉴的部分 | 适用边界 |
| --- | --- | --- | --- |
| [RoleLLM 论文](https://arxiv.org/abs/2310.00746) | 包含角色档案、基于上下文的指令生成、说话风格模仿和角色条件指令微调四个阶段 | 将“人物知道什么”“怎样表达”“如何训练”分开组织 | 合成问答是训练材料，不自动成为历史证据 |
| [TimeChara 论文全文](https://arxiv.org/html/2405.18027v1) | 区分未来未知、过去在场、过去不在场和一般过去知识；比较普通 RAG、截止时间检索和分解判断 | 回答前检查时间及亲历资格；检索要有年代边界 | 原评测使用英文小说人物，迁移到真实历史人物仍需另建史料标注 |
| [RAG 原始论文](https://arxiv.org/abs/2005.11401) | 将生成模型与可检索的外部记忆结合 | 让文本证据保留在外部库，便于更新和定位 | 检索到的段落仍可能不相关、过时或与其他史料矛盾 |
| [ALCE 论文](https://arxiv.org/abs/2305.14627)与[作者代码](https://github.com/princeton-nlp/ALCE) | 同时评估语言流畅度、正确性和引用质量 | 分别检查“有引用”“引用支持该句”“需要证据的句子均有支持” | 其原有数据集和自动评估器不能直接判定中文史学争议 |
| [CharacterEval 论文](https://arxiv.org/abs/2401.01275)与[作者代码](https://github.com/morecry/CharacterEval) | 提供中文多轮人物对话、人物档案和多维评估流程 | 借鉴中文多轮测试和人工标注方式 | 人物表现分数不能替代历史事实审查 |
| [LoRA 原始论文](https://arxiv.org/abs/2106.09685) | 冻结预训练权重，通过低秩可训练矩阵做任务适配 | 后期以较少训练参数改进表达和遵守角色规则的能力 | 参数效率不是事实保证；错误训练材料仍会被学入模型 |

TimeChara 特别提示了一个容易被忽视的问题：无差别地给角色补充相关文本，可能使它说出该时点不应知道的信息。其论文中，时间一致性和人格一致性的评分也并不总是同步提高。因此，本项目需要把年代正确和出处正确作为单独的验收项，而不是只问模型“像不像这个人”。[来源：TimeChara 第4、5节及附录](https://arxiv.org/html/2405.18027v1)

## 史料应保存哪些区别

文献类型与可信度不能简单划等号。正式出版的本人文章能证明“该版本如何呈现其公开表达”；它不能自动证明所有叙述都是完整的事件经过，也不能直接揭示私人动机。回忆录能提供见闻及回忆者视角，但其写作时间、当时是否在场、记忆间隔、编辑过程和其他证据都影响可用范围。

美国图书馆协会的史料使用指南要求考虑作者、受众、成文语境、编辑或翻译改变，以及资料能回答和不能回答的问题。这些问题适合转成资料库的必填元数据。[来源：Using Primary Sources Online](https://www.ala.org/rusa/sections/history/resources/primarysources/using)

建议按“用途资格”管理资料，而不是给一本书一个永久的可信度分数：

| 资料 | 可以直接支持什么 | 进入人物回答前还要确认什么 |
| --- | --- | --- |
| 本人署名原著、书信、讲话的已核验文本 | 某一版本的具体表述 | 原作日期、记录方式、后期修订、上下文、是否为引述他人 |
| 语录选编 | 编者选入的原文片段及编排 | 对应原篇、删节范围、主题分类是否属于编者、原句的条件和对象 |
| 同时代档案、会议记录、日记 | 当时记录下的事件或表达 | 记录者、是否在场、记录可靠性、传抄与整理过程 |
| 本人或他人事后回忆录 | 回忆者对某事的叙述 | 事件日期、回忆成文日期、亲历或转述、交叉印证和相冲突记载 |
| 学术传记、研究文章 | 研究者的解释与综合 | 论断依据及争议范围；不得直接写为人物自述 |
| 无出处网络名言、模型生成故事 | 检索线索或待核实候选 | 未找到可核原文前，不作为引文、人物记忆或训练事实 |

对同一句话，应分别存储：原文、OCR 转写、校订文本、校订说明。OCR 错字不能靠语言模型无痕改正；同一语录在选编和原篇中重复出现，也不能被计为两个独立证据。

## 需要两种明确的对话模式

**史料解释模式**适合学习与研究。它可以跨阶段比较文章，说明材料异同和思想变化，采用第三人称并提供出处。

**指定年代模拟模式**适合人物对话。必须固定角色截止日期，并只使用当时有依据可知的经历、概念和表达。首次进入时说明这是基于史料的模拟；人物化表达不能把推测包装成新的历史原话。

遇到现代问题时，解释模式可以讨论某种思想框架的可能应用，并标为当代推演；指定年代模拟模式不能直接宣称人物曾对现代事物形成某种具体立场。用户的问题本身也可能包含未来事实，不能因为用户说了，系统就把它写入角色的既有记忆。

## 年代过滤要处理版本时间

至少分开保存以下时间，不能只取书名或文章标题中的年份：

1. **事件时间**：被讨论的事情何时发生。
2. **原作或原讲话时间**：文本最初产生于何时。
3. **修订与编纂时间**：后期是否有改写、补注、选编或重新定题。
4. **现存版本出版时间**：本次 PDF 所代表的版本何时出版。
5. **角色可知时间**：有证据支持角色何时获知该事，不一定等于事件时间。
6. **回忆成文时间**：回忆录是事后何时记录的；不能并入事件时间。

例如，用1967年或1977年的印本构建更早时期的人物，不能仅因某篇标注早年日期就把该页全部视作当年的表达。后加注释、修订说明、编者解释以及修订过的段落，应单独标识。没有版本校勘时，早期模拟中的逐字引用须提示其依据为现存后期版本，或转为带出处的审慎概括；不能声称逐字恢复当年原貌。这是本项目的版本控制要求，不是对尚未逐篇核验版本差异的断言。

先在候选资料中实施时间与来源过滤，再做关键词或向量检索。不要检索全库以后仅靠提示词要求模型“忘掉未来”。过滤仍不能清除基础模型已记住的未来知识，因此生成后还需要年代核对。

## 将价值观与哲学观转成可执行规则

人物档案不宜只有“务实”“辩证”“坚定”等形容词。每个思想条目都应说明适用条件、推理方式、证据和变化范围。

一个可审阅条目的结构可以是：

```json
{
  "principle_id": "待分配",
  "label": "从原文归纳的原则名",
  "valid_from": null,
  "valid_to": null,
  "historical_problem": "原文针对的问题",
  "audience": "原文的对象或受众",
  "decision_rule": "遇到何种情况时，倾向先判断什么，再采取什么步骤",
  "conditions_and_exceptions": [],
  "supporting_source_ids": [],
  "counter_or_changed_source_ids": [],
  "confidence": "unreviewed",
  "status": "analytical_summary_not_original_quote"
}
```

本项目可围绕“认识如何形成与检验”“如何分析矛盾与条件”“怎样调查与作判断”“个人与集体、组织与群众的关系”“目标、阶段与手段如何安排”等问题建立候选条目。每条是否成立、适用于哪一阶段，必须由已核验原文决定。它们是阅读问题，尚不能凭这些问题直接宣布人物终身具有一组固定答案。

重点保存相同主题在不同文章、不同时期的异同：是表述不同、情境不同、策略变化，还是确有观点修订。系统不应为了“人格一致”而自行消除矛盾，也不应把一段针对具体历史斗争的修辞推广成所有生活问题的普遍建议。

表达层应另外保存句式、论证节奏、设问、类比等可观察特征。回答先由证据与阶段规则决定内容，最后再调整表达，避免口吻反过来制造事实。

## 推荐的数据组织

正文资料块保留以下字段。空值意味着尚未核实，不能由模型补成看似准确的日期或页码。

```json
{
  "source_id": "唯一资料编号",
  "document_id": "文献编号",
  "document_title": "文献题名",
  "article_title": null,
  "author_or_speaker": null,
  "recorder_or_editor": null,
  "source_type": "author_text|speech_record|quotation_compilation|memoir|research|editor_note",
  "event_date_start": null,
  "event_date_end": null,
  "composition_date": null,
  "revision_date": null,
  "edition_publication_date": null,
  "known_to_character_from": null,
  "historical_stage": null,
  "pdf_page": 1,
  "printed_page": null,
  "text_raw": "原始提取或 OCR 文字",
  "text_corrected": null,
  "parent_context_id": null,
  "original_article_source_id": null,
  "topics": [],
  "ocr_status": "unreviewed",
  "quote_verified": false,
  "eligible_for_early_period_verbatim_quote": false,
  "disputed_with_source_ids": []
}
```

`pdf_page`是从1开始的 PDF 物理页序，`printed_page`是书内印刷页码，两者须分别核实。按自然段和文章切分，保留标题、日期、前后文链接；不要把几篇不同年份文章拼成一个资料块。正文、脚注、编者说明、目录和序言应可分别筛选。

初版可用全文关键词检索和人工主题标签；加入向量检索后，建议与关键词结果合并并重排。具体分块大小、召回数量和模型选择应由中文检索评测确定，现阶段无需先下载大型模型。

## 一次回答的工作流程

1. 读取对话模式、角色日期和用户问题，识别是否涉及未来事件、争议记忆、直接引文或现代推演。
2. 筛选资料资格：年代、版本、作者、正文或注释、OCR 校对状态、是否为原篇或重复选编。
3. 检索候选段落，回到完整段落和必要前后文。对价值判断与哲学概括，至少检查其适用条件；不能只摘取包含关键词的一句。
4. 形成简短的证据清单：哪些事实可直接说、哪些只能归纳、哪些资料冲突、哪些无依据。不向用户暴露内部推理过程。
5. 生成回答，将原话、概括和推演分开。逐字引文必须匹配已核文本；其他内容不得加引号伪装成原话。
6. 检查每个事实句、时间、亲历描述和引用是否得到支持。删去无支持的补充，或明确证据不足。
7. 保存用户问题和本轮已用来源以便复核。用户聊天内容只属于本轮会话记忆，不能自动变成人物历史事实。

引用建议采用“篇名、原作日期、所据卷与版本、印刷页码或 PDF 页序、资料编号”。未核实的印刷页码不要猜填。界面可把详情折叠，但事实依据应可展开查看。

## RAG 与训练的投入次序

| 路线 | 适合解决的问题 | 在本项目的顺序 |
| --- | --- | --- |
| 人物提示词或角色卡 | 固定模式、年代、口吻和回答规范 | 作为入口，但不承载全部文献 |
| 关键词检索与 RAG | 找原文、定位出处、更新资料、按年代过滤 | 第一版主线 |
| 经人工核验的示例问答 | 教会模型区分原话、解释、推演和缺证回答 | 与检索版一起迭代 |
| SFT | 在资料和测试成熟后改善稳定表达与任务遵守 | 用对照实验确认必要性后再做 |
| LoRA | 以较少可训练参数实现上述适配 | 是训练实现方式，不是 RAG 的替代方案 |
| 偏好训练或奖励模型 | 有足够可靠对比标注后优化多项表现 | 后续选项；不能用“更像人物”奖励抵消史实错误 |

SFT 或 LoRA 的样本应覆盖正确引文、年代未知、未在场、史料冲突和证据不足等情形。由模型从史料生成的问答必须保留源段落并经复核；未经复核的合成故事不应进入人物记忆库。测试集按文章或独立资料分组留出，避免同一句语录在原篇与选编两处重复，分别落入训练集和测试集造成虚高分数。

## 建议的验收集

先做一个小而经过人工核验的中文测试集，再扩大。下列数量是本项目首版的建议配置，不是现成实验结果。

| 类别 | 建议题量 | 主要检查 |
| --- | ---: | --- |
| 原话与出处 | 20 | 引文是否逐字一致，篇名和页序是否正确 |
| 原篇上下文与限定条件 | 15 | 能否区分语录摘要和原篇完整论证 |
| 年代边界与未来问题 | 20 | 早期角色是否错误使用后期事实、文本或修订 |
| 亲历与转述 | 10 | 是否把别人的回忆变成“我亲眼看见” |
| 同主题分阶段差异 | 15 | 能否指出变化与情境，而非强行统一 |
| 伪名言与错误前提 | 10 | 能否识别库中无据，避免迎合用户补造 |
| 多轮一致性与现代推演 | 10 | 连续追问后是否遗失年代、把类比说成历史立场 |

合计100题。每题保存允许来源、应包含要点、禁止断言、角色日期及人工判断依据。至少对争议、年代和引文题做人工复核；LLM 评委可辅助筛查，不能单独决定历史真实性。

验收分别报告：事实支持率、引文准确率、出处可定位率、未来知识泄漏率、亲历错误率、无据断言率、分阶段一致性、多轮可用性和表达相似度。前三类基础错误应作为阻断项处理；表达相似度较高不能弥补它们。

可设计的压力测试包括：把角色固定在某一早期日期，诱导其回顾后期事件；给出伪造名言要求承认；把回忆录转述诱导成亲历；要求概括一个跨时期主题；连续十轮后突然改问截止日期以后的结果。具体历史题须在本次 PDF 校核后再填写标准答案。

## 本项目适合交付的第一版

第一版应包含六本 PDF 的可追溯转写、提取与 OCR 质量清单、篇目和年代索引、经核验的哲学与价值观条目、一个能调用本地检索的 skill 草案，以及上述测试的种子题。它是可审阅的史料对话原型，不等于已经训练并验证完成的人物模型。

若材料主要是选集和语录，系统最有把握的范围是“公开文本中的论证、概念和表达”。要扩展到完整人生经历、私人交往和未收录时期，应另补年谱、书信、档案、经辨析的回忆录和研究材料，并继续保留不同材料各自能够支持的范围。
